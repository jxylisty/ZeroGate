# 09 · AutoClaw 账号封禁事故复盘（2026-09-23）

用户报告："昨天还好好得，今天直接封号了"。两个 AutoClaw 账号（`1a09c829…`、`54243632…`）
先后被上游封禁（403 / `code:410004 账号已被封禁`），余额查询仍正常。

## 一、事故链（日志还原）

```
12:24  5424 号 token 失效（401 Invalid token / 410000）
         ↓
12:24-13:06  客户端每 8-10 秒重试一轮；daemon 每轮把账号池打一遍
         ↓  日志中 410004 累计出现 218 次
13:06  5424 号被封（410004）
         ↓
10:56  1a09 号更早被封（它自己没有 401，疑同设备/IP 关联）
```

**关键证据**：`grep 410004 data/app.log | wc -l` → 218 次；
请求间隔 8-10 秒（`10:56:12 → :20 → :29 → :39 → :50 …`）来自客户端自动重试。

## 二、根因：两层叠加，第二层是放大器

### 第一层（放大器）：`9cf661f` 把重试上限改成了时间窗

| | 改动前 | 改动后（9cf661f，2026-09-21） |
|---|---|---|
| 重试次数 | `MaxFailover = 2`（最多 2 次） | 无上限，`for attempt := 1; ; attempt++` |
| 终止条件 | 次数用完 | **270 秒时间窗** |
| 退避 | `attempt × 500ms` | 递增封顶 5s |

设计意图是好的（忙窗自愈，避免用户手动重发），但**没有为"封禁"这类不可恢复错误留出口**。
虽然在 `isFailoverable` 里加了 `410004 → return false`（立即放弃），
但**客户端每 8 秒重来一轮**，daemon 每轮又把所有账号打一遍 —— 单请求有上限，
**整体没有**。

### 第二层（结构缺陷）：全池不可用仍转发上游

`handler.go` 的账号轮换遇到 `ErrBanned` 后是 `continue`（换下一个号），
设计意图是"换号容灾"。但**所有号都封了的时候，等于每个请求把所有号各打一遍**，
把"账号已封禁"反复送给上游，加深风控标记。

### 第三层（盲区）：失败请求不落渠道

失败路径的审计记录 `Channel` 字段为空（只记了错误文本），
排查"是谁在打、打到哪个渠道"只能翻 app.log。审计里所有记录 `client` 都是 `Default`
（客户端未带标识），进一步增加了定位难度。

## 三、修复

| # | 位置 | 改动 |
|---|---|---|
| 1 | `internal/pool/pool.go` | 新增 `HealthyCount()`：返回健康/总数，供熔断判断 |
| 2 | `internal/server/handler.go` | **渠道级熔断**：`breaker` map + `breakerOpen/Trip/Reset`。整池健康数=0 → 置位 60s，期间**不转发上游**直接 503；成功请求清除熔断（半开恢复） |
| 3 | `internal/autoclaw/autoclaw.go` | 重试窗口 `270s → 45s`，新增 `retryMaxAttempts = 6` 硬上限；窗口耗尽改返 **429**（原 502 会被客户端当"服务故障"继续重试） |
| 4 | `internal/server/handler.go` | 熔断路径记 `lastCandKind`，失败审计带上 `Channel` |

**实测**：整池禁用时 0.15 秒快速失败（修复前要挂 270 秒），
响应 `autoclaw 渠道账号池整体不可用（2 个账号全部禁用/冷却），已暂停转发`；
审计记录 `channel=autoclaw status=503`。

回归测试 `internal/server/handler_breaker_test.go` 4 项：
熔断置位/到期半开/清除、渠道隔离、健康计数（全禁用=0）、封禁后不健康。

## 四、铁律（写进 AGENTS.md）

1. **不可恢复错误（封禁/凭证失效）必须立即中断，绝不长时间重试** —— 上游会把"持续重试"判定为恶意。
2. **渠道级熔断优先于账号级轮换**：整池不可用时停止转发，而不是逐号重试。
3. **客户端会重试**：daemon 必须假设"失败后客户端马上再来"，因此失败要快速返回
   且语义明确（429/503 + 明确文案），不要用会被误读为"稍后能好"的 502。
4. **审计必须覆盖失败路径**并带上渠道，否则事后无法定位是谁在打。

## 五、后续建议

- 账号是否可解封未知：余额查询正常（`remain=6974/2000`）说明账号未注销，
  但对话接口全部 403。可等待数日或走官方申诉。
- ZCode / Trae 客户端若仍配置 autoclaw 模型，建议先移除该模型，避免恢复后再次触发。
- 若其他渠道出现同类模式（客户端重试 + 整池不可用），熔断会自动接管，无需额外配置。
